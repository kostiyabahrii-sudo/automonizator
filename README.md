# Pinterest Auto-Poster

Автоматична публікація пінів у Pinterest із заготовлених картинок: раз на
5-6 годин (з випадковим зсувом), назва піна = ім'я файлу, опис і теги —
заготовлені заздалегідь.

## Як це працює і чому це не "ботова активність"

Скрипт публікує піни через **офіційний Pinterest API v5** (Content
Publishing API) — той самий механізм, яким користуються легальні сервіси
на кшталт Tailwind, Buffer, Later для запланованих публікацій. Це:

- **не** браузерна автоматизація (без Selenium/Playwright, без емуляції
  кліків живої людини) — саме такі методи Pinterest активно детектить і
  банить за них;
- офіційно авторизований застосунок з OAuth-токеном, запити йдуть в межах
  дозволених рейт-лімітів API;
- інтервал між постами — не рівно "кожні N годин", а випадкове число з
  діапазону 5–6 год при кожній публікації, тож не виглядає як публікація
  за жорстким розкладом.

Важливо чесно розуміти межі: жоден інструмент не може "гарантувати", що
Pinterest завжди просуватиме конкретний пост — це залежить від якості й
унікальності контенту, залучення аудиторії тощо. Скрипт прибирає ризик
бану за *технічну* автоматизацію (використовуючи легальний API замість
емуляції браузера), але не є способом обійти алгоритми ранжування.

Процес **не є довготривалим демоном**, що постійно висить у пам'яті:
запускається через `cron`/`systemd timer` раз на 15 хв, перевіряє "чи
настав час постити" (файл стану) і за долі секунди завершується, якщо ще
не пора. Реальна робота (завантаження картинки) відбувається лише раз на
5-6 год і займає кілька секунд. Фонового споживання пам'яті між запусками
немає взагалі.

## Встановлення

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
cp config.example.yaml config.yaml
```

### 1. Створити застосунок Pinterest

1. https://developers.pinterest.com/apps/ -> Create app.
2. Вписати `PINTEREST_APP_ID` / `PINTEREST_APP_SECRET` у `.env`.
3. У налаштуваннях застосунку додати Redirect URI (може бути
   `https://localhost/callback` — сама сторінка не має відповідати,
   важливий лише `code` у адресному рядку після редіректу).

### 2. Авторизувати акаунт (одноразово)

```bash
python -m pinterest_autopost.oauth_setup
```

Скрипт видасть посилання для авторизації в браузері, попросить встановити
код з redirect-URL і сам збереже `PINTEREST_REFRESH_TOKEN` у `.env`. Далі
`access_token` оновлюється автоматично, участь людини більше не потрібна.

### 3. Знайти board_id і вписати в `.env`

```bash
python scripts/list_boards.py
```

Скопіювати потрібний ID у `PINTEREST_BOARD_ID`.

### 4. Перевірити з'єднання

```bash
python scripts/test_connection.py
```

### 5. Налаштувати `config.yaml`

Заповнити `description` (текст + теги, як у прикладі), за бажанням
`link`, діапазон `interval_hours_min/max`.

### 6. Покласти картинки

Готові файли — у `posts/pending/`. Назва файлу стане заголовком піна
(підкреслення/дефіси -> пробіли, Кожне Слово З Великої). Наприклад
`kitchen_design_01.jpg` -> заголовок "Kitchen Design 01".

### 7. Запустити

Разова публікація (для перевірки, ігнорує таймер):

```bash
python -m pinterest_autopost.scheduler --force
```

Постійна робота у фоні (обери один варіант):

**Варіант A — cron (найпростіше):**

```bash
bash scripts/install_cron.sh
```

**Варіант B — systemd timer:**

```bash
sudo cp systemd/pinterest-autopost.service systemd/pinterest-autopost.timer /etc/systemd/system/
sudo sed -i "s#/ШЛЯХ/ДО/automonizator#$(pwd)#" /etc/systemd/system/pinterest-autopost.service
sudo systemctl daemon-reload
sudo systemctl enable --now pinterest-autopost.timer
```

Обидва варіанти запускають короткий процес раз на ~15 хв, а не постійний
фоновий демон — пам'ять витрачається лише на секунди виконання.

## Структура

```
pinterest_autopost/
  config.py          # config.yaml + .env
  pinterest_client.py# запити до Pinterest API v5 (OAuth refresh, create_pin)
  poster.py          # вибір картинки, заголовок з імені файлу, публікація
  scheduler.py        # entrypoint для cron: "чи час постити"
  oauth_setup.py      # одноразова інтерактивна авторизація
posts/
  pending/            # сюди кладеш готові картинки
  posted/             # архів опублікованого
  failed/             # картинки, які не вдалось запостити (дивись лог)
state/state.json       # access/refresh token, час останнього/наступного поста
logs/poster.log         # лог публікацій і помилок
```

## Нотатки

- Ліміт Pinterest API v5 — суттєво більший за 4-5 пінів/день, тому в
  рамки рейт-лімітів вписуємось з великим запасом.
- Поле `alt_text` і `title` обрізаються під ліміти API (100/500 символів)
  автоматично.
- Якщо публікація падає з помилкою — картинка переїжджає в
  `posts/failed/`, а не губиться і не публікується повторно "наосліп".
  Причина завжди буде в `logs/poster.log`.
- Схема API v5 (поля `media_source`, `/oauth/token` тощо) звірена з
  документацією Pinterest Developer станом на момент написання; якщо
  Pinterest змінить формат, `scripts/test_connection.py` одразу покаже
  конкретну помилку від API для діагностики.
